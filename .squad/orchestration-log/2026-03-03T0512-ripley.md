## Summary

Frontend was catching API errors but displaying a generic "Failed to generate meal plan" message instead of showing the actual error from the API response. This prevented users from understanding why their request failed (e.g., "Household already has an active or in-progress meal plan").

## Work Done

1. **Diagnosis:** API returns structured error responses with a `detail` field containing actionable messages. Frontend ApiError class captures this in `body` property but wasn't extracting it.

2. **Fix:** Updated `apps/web/src/app/meal-plan/page.tsx` error handler to extract and display the `detail` field from API errors:
   ```typescript
   catch (err) {
     const message =
       (err && typeof err === "object" && "body" in err
         ? (err.body as { detail?: string })?.detail
         : null) ?? "Generic fallback message";
     setError(message);
   }
   ```

3. **Testing:** All 117 API tests pass, 56 worker tests pass, Next.js build succeeds.
