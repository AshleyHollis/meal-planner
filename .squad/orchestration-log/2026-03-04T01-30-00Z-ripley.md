## Summary

Meal plan generation was failing with "Expected ~21 recipes for 3 meal types (±2), got 13" and many "ingredient X not in inventory" errors. The root cause: `validate_constraints()` required every recipe ingredient to exist in household inventory, blocking generation when the LLM naturally includes ingredients not yet stocked (which is correct — those become grocery list items).

## Work Done

**Files Modified:**
1. `services/workers/meal_plan_generator/validator.py` — removed check #4 (inventory ingredient validation)
2. `services/workers/meal_plan_generator/prompts.py` — updated requirement 6 to prioritize (not require) inventory items

**Changes:**

- **validator.py:** Removed the loop that checked `if ingredient not in inventory`. Kept function signature unchanged for backward compatibility.

- **prompts.py:** Changed requirement 6 in `SYSTEM_PROMPT` constant from:
  > "Use ingredient names that match the provided inventory list"
  
  to:
  > "Prioritize using ingredients from the provided inventory, especially items expiring soon. Recipes MAY include ingredients not in inventory — those will be added to the grocery list."
  
  Also updated `format_system_prompt()` function to propagate the same change.

**Rationale:** Inventory awareness is guidance (handled via prompt), not a validation gate. Hard gates belong only to safety constraints (allergies, equipment modes) and structural constraints (recipe count, servings). The grocery list exists precisely to surface items not yet in stock.
