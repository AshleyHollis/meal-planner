## Changes

- `services/workers/meal_plan_generator/generator.py`:
  - `_persist_plan()`: Changed `result.scalar_one()` → `result.scalar_one_or_none()` with explicit None guard
  - `_mark_failed()`: Same pattern for graceful handling when plan deleted mid-generation
- Pattern: scalar_one_or_none() + None check + warning log + early return

## Rationale

Workers run asynchronously. Plan can be deleted between LLM call and DB write. `scalar_one()` raises `NoResultFound` → propagates as exception → `_mark_failed` also fails. Using scalar_one_or_none() prevents double failure and state corruption.
