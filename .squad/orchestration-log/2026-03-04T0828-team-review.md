## Team Findings Summary

### Dallas — Architecture & Feature Completeness (Claude Opus 4.6)

**Critical Issues Found: 3**
1. **Leftovers/Freezer in LLM**: Prompt formatters exist but data not fetched; AI cannot prioritize expiring items or freezer defrost timing
2. **ShoppingTrip Model Missing**: Trip CRUD, filters, and per-trip state tracking completely absent; localStorage-only workaround in frontend
3. **Substitution Doesn't Update DB**: Grocery list diff computed but never persisted to GroceryItems table; stale data risk

**Important Issues: 6**
- No `add-staples` endpoint for bulk staple-to-grocery addition
- "Cook This" quick suggestion creates no persistent meal slot (spec says it should)
- Adapt recipe route is stub with TODO comment (service layer isolated from route)
- Save recipe variation route returns mock response (unimplemented)
- Skipped meals incorrectly timestamped with `cooked_at` (affects history lookback)
- Leftover PATCH endpoint only marks `used_at`, cannot update portions/location/expiry

**Minor Issues: 5**
- Grocery regeneration doesn't set `preferred_store` from product mappings
- Cuisine type not updated during substitution (prompt doesn't ask LLM)
- No 409 response on double-cook (safety ok, API contract differs from spec)
- Ingredient.default_storage lacks explicit enum constraint
- Rating system allows single low rating to block recipe (no minimum count threshold)

### Ash — UX Completeness Audit (Claude Sonnet 4.6)

**Critical Issues Found: 8**  
All block normal user workflows. Leading problems:
- **Silent failures (6)**: Grocery check, inventory edit/remove, product delete, mark cooked/skip, favorite toggle — all have bare `catch { // silent }` with no error UI
- **404 dead ends (2)**: `/inventory/[id]` and `/products/[id]` routes link to non-existent detail pages; every click is a failure

**Important Issues: 19**  
Mix of missing navigation, broken patterns, and incomplete states:
- No Home/Dashboard link in desktop sidebar (only accessible via logo click)
- Recent activity rows not interactive (clickable but go nowhere)
- No grocery list link from meal plan detail (user must navigate backward manually)
- Meal plan cards show generic "Plan for the week" with no meal preview or image
- Delete plan only available for "failed" status (no cleanup for draft/completed)
- 4 missing Retry buttons on error states (dashboard, history load-more, preferences, quick suggestions)
- Preferences panel uses hardcoded placeholder CURRENT_MEMBER_ID ("current" user never fetched)
- Quick Suggestions cards lack meal images (inconsistent with dashboard display)
- Recurring Meals empty state bare (no icon/CTA like other empty states)
- Delete actions lack confirmation dialogs (preference, recurring meal — instant loss)
- Currency formatting inconsistent (`$X.XX` vs `AUD X.XX`)
- ErrorBoundary component exists but never used

**Minor Issues: 9**  
Polish and duplication:
- `getNextMonday()` defined in 2 places (drift risk)
- `DAY_LABELS` duplicated in 4+ files
- Grocery list index empty state uses bare div (should use EmptyState component)
- Products search shows text "Searching…" instead of spinner
- All pages share same browser tab title "Meal Planner" (can't distinguish tabs)
- Recurring Meals page narrower than others on desktop (missing `lg:max-w-7xl`)
- Rating loading state tracked but never shown (skeleton missing)
- `WeeklyPlanView.tsx` component exists but is unused/unimported

## Cross-Team Consensus

### Severity Ranking
1. **P0 (Blocks users)**: 8 silent failures (UX), 3 fundamental feature gaps (Dallas), 404 dead ends
2. **P1 (Confusing/broken)**: 19 UX incomplete states, 6 missing integrations (Dallas), 3 spec gaps (Bishop)
3. **P2 (Friction)**: 9 UX polish, 5 minor bugs (Dallas), 3–4 test gaps (Lambert)

### Root Causes
- **Silent error handling**: Patterns set during MVP have persisted ("for POC" comments now in production)
- **Feature stubs**: Adapt/save-variation routes never connected to service layer
- **Data layer gaps**: Leftovers/freezer not fetched for AI; substitution changes not persisted
- **Missing entities**: ShoppingTrip exists in spec but never modeled; no trip → user data loss
- **Placeholder code**: CURRENT_MEMBER_ID hardcoded; backend auth flow never completed
- **Testing under-representation**: E2E focuses on happy paths; CRUD workflows (edit/delete) untested
