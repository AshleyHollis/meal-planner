### Domain Research
- No competitor combines expiry-prioritized AI meal planning + equipment-specific cooking steps + multi-shop grocery lists. Genuine white space.
- Hybrid LLM + constraint validation is the pragmatic approach for recipe generation (CHI 2025).
- Ninja Combi has NO smart connectivity/API. 14 cooking modes. Informational only.
- Inventory accuracy decay is the #1 adoption risk. Auto-deduction essential.
- Schema.org Recipe property names improve LLM structured output quality.
- Ingredients must be first-class entities for inventory math, shopping consolidation, substitution.
- Store quantities in canonical metric units (g, ml, units) internally.
- P1-P4 form the true MVP core loop; P5+ are enhancements.
- Static ingredient substitution table sufficient for MVP. AI augments at runtime.
- List-based weekly view (not calendar grid) better for mobile MVP.
- Paprika-style auto-timer detection from recipe text is gold standard for cooking UX.
- Web Speech API: no Firefox support. Chrome/Edge/Safari only. Acceptable.
- Screen Wake Lock API critical for cooking mode. Chrome 84+, Edge 84+, Safari 16.4+.
- LLM cost ~$0.05-0.15 per weekly plan generation. Acceptable for personal use.

### Design Phase
- yt-summarizer uses `AddExecutable` (not `AddPythonModule`) for workers in Aspire -- workers have separate `.venv` directories and run via `__main__.py`. Meal-planner worker must follow same pattern.
- yt-summarizer DB connection supports ADO.NET connection strings from Aspire (`ConnectionStrings__<name>`) with automatic conversion to SQLAlchemy async URL. Reuse `convert_ado_connection_string` logic exactly.
- yt-summarizer models use `UNIQUEIDENTIFIER` PK type mapped via `type_annotation_map` on `Base`, not generic `UUID` column type. Critical for SQL Server compatibility.
- yt-summarizer K8s manifests use ArgoCD sync waves (namespace=0, secrets=1, API=2, workers=3) for ordered deployment. Follow same wave numbering.
- Cook-time adaptation must be synchronous (API-side LLM call) because NFR-02 requires <10s latency. Only meal plan generation goes through the worker queue.
- Auto-provisioning household on first login avoids any setup wizard. JWT `sub` claim maps to `HouseholdMember.auth0_user_id`. Household created inline during auth middleware.
- Grocery list is materialized (persisted tables) not computed on-the-fly. Required for check-off state persistence and shopping complete workflow.
- 13 database tables total. All have UUID primary keys, household_id scoping where relevant, and explicit indexes.
- Single worker (meal_plan_generator) is sufficient for MVP. Unlike yt-summarizer's 4 workers, meal-planner has only one async job type.
- LLM provider abstracted behind `LLM_PROVIDER` env var. Both Anthropic and OpenAI supported. Cost ~$0.04-0.09 per plan generation, well under NFR-10 $0.15 target.
- Ingredient seed data delivered via Alembic data migration (not separate script) so it runs automatically with `alembic upgrade head`.

## Learnings
### Testing Infrastructure
- UNIQUEIDENTIFIER (MSSQL-specific) not supported by SQLite. Use `@compiles(UNIQUEIDENTIFIER, "sqlite")` to render as `VARCHAR(36)` for test compatibility.
- aiosqlite added as dev dependency for async in-memory SQLite testing.
- Test conftest uses dependency_overrides on get_session, get_current_user, get_current_household_id to mock auth and DB for integration tests.
- TimestampMixin uses `func.sysutcdatetime()` (MSSQL), but tests pass explicit created_at/updated_at values so server defaults are not invoked.
- Service-level tests that go through ORM `add_item()` (without explicit timestamps) need the `sysutcdatetime` SQLite shim registered in conftest's engine fixture via `dbapi_conn.create_function()`.
- Route integration tests: conftest's `_override_session` doesn't commit, so data created via HTTP POST is not visible to subsequent GET requests in the same test. Seed data directly via session fixture + model inserts, then test HTTP endpoints individually.
- HTTPBearer (FastAPI security) returns 401 (not 403) when no Authorization header is present (with the custom error handler registered).
- For 401 unauthorized tests, must override `get_session` even though auth fails first, because FastAPI resolves independent dependencies in parallel — `get_session` would error trying to connect to a real DB.
- MealPlan has FK to Households. Tests for cross-household isolation that call `create_plan` must seed a real Household row for the other household_id, not just use a random UUID.
- Prompt builder tests use `types.SimpleNamespace` to mock ORM models (InventoryItem, Equipment, EquipmentMode, Ingredient). No DB needed since prompt functions are pure string formatters.
- prompts.py accesses `m.min_temp_celsius` / `m.max_temp_celsius` on EquipmentMode but the ORM model has `min_temp` / `max_temp`. Mocks match actual code behavior (using _celsius suffix).
- Frontend test infra: vitest 4.x + @testing-library/react + @vitejs/plugin-react + jsdom. vitest.config.ts needs `environment: "jsdom"` and react plugin for JSX transform. Use `vi.useFakeTimers()` + `vi.setSystemTime()` to control date-dependent component output. Tests in `src/__tests__/`.
- API client tests: Use `vi.resetModules()` + dynamic `import()` via `freshApi()` pattern to get a fresh module-level token cache per test. Mock `global.fetch` with `vi.stubGlobal("fetch", fetchMock)`. First fetch mock resolves token from `/auth/access-token`, second resolves the API response. Use `// @vitest-environment node` since API client tests don't need DOM.
- Integration tests need a custom client fixture with `StaticPool` + `connect_args={"check_same_thread": False}` for aiosqlite in-memory DB to share state across sessions. The `_override_session` must `await sess.commit()` after yield so cross-request data persists. The default conftest `_override_session` doesn't commit, which is fine for isolated route tests but breaks multi-step lifecycle tests.
- `GroceryService.complete_shopping` had a latent bug: it didn't refresh the `ingredient` relationship on newly created `InventoryItem` objects, causing `MissingGreenlet` when `InventoryItemResponse.model_validate()` tried to access `ingredient`. Fixed by adding `await self.session.refresh(inv, attribute_names=["ingredient"])` after flush.

Env vars: AUTH0_DOMAIN, AUTH0_CLIENT_ID, AUTH0_CLIENT_SECRET, AUTH0_SECRET, APP_BASE_URL. Import Auth0Client from "@auth0/nextjs-auth0/server", Auth0Provider from "@auth0/nextjs-auth0/client".
- Auth0 v4 BFF pattern: client-side code fetches JWT via `/auth/access-token` endpoint (enabled by default via `enableAccessTokenEndpoint: true`). Token cached in memory with 60s early-expiry buffer. API client attaches `Authorization: Bearer <token>` header to all backend requests.
